# Portfolio redesign: amber-to-purple theme swap with section overhaul

A full visual redesign of a Next.js portfolio site, replacing the warm amber/magenta palette with a purple/pink/cyan color scheme and swapping fonts from Geist/Instrument Serif to Space Grotesk/Inter/JetBrains Mono. Beyond the token swap, the Navbar, Hero, About, Work, and Experience sections were rewritten with new layouts, a Testimonials section was added, and the starfield canvas was simplified. The Marquee and Education sections were removed from page composition.

**Watch for:** Project cards dropped all external links (GitHub, demo URLs) — this is a functional regression, not just a visual change (confirmed). The About section replaced real biographical stats with generic placeholder numbers that may not reflect the actual person (confirmed). The Work section removed the category filter, reducing discoverability for portfolios with many projects (confirmed).

## High-level view

The design system swap (globals.css + tailwind.config.ts + layout.tsx) cleanly migrates color tokens and fonts through CSS custom properties, so the change propagates everywhere without touching individual components' color references. The hue shift from 260/320 to 270/325 is narrow enough that existing accent usages remain coherent.

The Navbar simplifies from a glass-pill link group with a "Resume" download button to bare links with an internal "Let's Talk" anchor. This trades an outbound conversion action (resume download) for an inbound one (scroll to contact), which is a deliberate product decision but loses the resume distribution path entirely.

The Work section was gutted from a stateful filtered grid with project links, highlights, and category tabs to a static featured/rest split with placeholder gradient rectangles. The visual design is cleaner but the component lost its interactive filtering, external links, highlight text, and hover-radial effect — the portfolio no longer links to actual work artifacts.

The ParticleField rewrite is well-structured: removes the constellation lines, adds mouse parallax, shifts to blue-white star colors, and properly respects `prefers-reduced-motion`. The tier-based size distribution gives a more natural starfield appearance.

The new Testimonials section uses hardcoded data inline rather than pulling from a content file, breaking the established content/component separation pattern used by every other data-driven section.

## Work section: functional regression behind a visual simplification

The original Work component was the most interactive piece of the portfolio: category filter tabs (`All | ML | Web | UI/UX | Automation`), `AnimatePresence` transitions between filtered sets, per-project highlights lists, and crucially, rendered links to GitHub repos and live demos when available in the data model.

The new version splits projects into `featured` (full-width cards) and `rest` (2-column grid) with gradient placeholder visuals and tech tag pills. The `projects.ts` data file still carries `links.github`, `links.demo`, `highlights`, `subtitle`, `category`, and `period` fields — none of which are rendered anymore. The data contract is wider than the UI consumes.

For a portfolio site, the inability to click through to actual project artifacts is a significant gap. A visitor sees "Deepfake Image & Video Detection" with tech tags but has no way to reach the code or demo. The original component rendered these:

```tsx
{p.links?.github && (
  <a href={p.links.github} ...><Github size={14} /> Code</a>
)}
{p.links?.demo && (
  <a href={p.links.demo} ...><ArrowUpRight size={14} /> Live</a>
)}
```

This was removed entirely rather than restyled.

## Content/component separation break in Testimonials

Every other data-driven section imports from `content/*.ts`: `profile.ts`, `projects.ts`, `experience.ts`, `education.ts`. The new Testimonials component defines its data array inline:

```tsx
const testimonials = [
  { name: "Prof. Rajesh Kumar", role: "Faculty Advisor, GBU", quote: "..." },
  // ...
];
```

This works but breaks the established pattern. When content needs updating, a maintainer won't find it where they expect. The fix is trivial — extract to `content/testimonials.ts` and import.

## Navbar: outbound link trade-off

The original Navbar rendered a filled "Resume" button linking to `profile.resumeUrl` (an outbound PDF/link). The redesign replaces it with a bordered "Let's Talk" button that scrolls to `#contact`. The mobile menu received the same treatment. Whether this is intentional depends on the portfolio's goals — if resume distribution is important (job-seeking mode), the path disappeared. If the goal is lead generation ("hire me for freelance"), the contact scroll makes sense and the "Currently available for freelance" status indicator in the Hero reinforces it.

## ParticleField: clean rewrite with one performance note

The starfield dropped the cursor constellation lines (the feature that drew SVG-like connections between nearby stars) and replaced it with a simpler halo effect for nearby stars plus whole-field parallax based on mouse position. The parallax calculation `(mx - W / 2) * 0.02` runs per-frame per-star but the values `px` and `py` are computed once outside the loop, so the per-star cost is just two additions — negligible.

One subtlety: the `spawn()` function is only called from `resize()` when `stars.length === 0`, meaning resizing the window after initial load never re-distributes stars. Stars that drifted off-screen during a resize will bounce back via the velocity inversion (`if (s.x < 0 || s.x > W) s.vx *= -1`), but stars whose positions are now beyond the new viewport boundary may sit invisible until they drift back. This is unlikely to be noticeable in practice (stars move slowly) but is a behavioral asymmetry with the original that spawned fresh on every resize.

## About section: generic stats replace specific ones

The original stats were specific to the person: "200+ Datasets cleaned & fed into ERP", "30 Days · Smart Campus boot camp", "2 Concurrent degrees". The new stats are generic portfolio template numbers: "2+ Years Experience", "10+ Projects Completed", "5+ Happy Clients", "3+ Awards Won". These read as placeholder content rather than authentic biographical detail. The shift from data-backed specificity to rounded estimates weakens the section's credibility signal.
